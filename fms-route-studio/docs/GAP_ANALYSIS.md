# 突き合わせ（上位要求 ↔ FRS）カバレッジ／ギャップ分析

> **本書のステータス**: ドラフト 0.1（2026-07-01）
> **目的**: `unmanned-requirements`（AutonomousDumptruck、以下 ADT）の **FMS 運航前工程 S-00／Dynamic route／寄り付き／複数台協調／機種プロファイル**に関する要求と、FMS Route Studio（FRS）の[要件定義書](REQUIREMENTS.md)・実装の**カバレッジを突き合わせ**、ギャップを洗い出す。
> **対象範囲の前提**: FRS は ADT の **FMS 側「動作定義（マップ/エリア/ルート設定）＋運航前データセット準備（S-00）＋経路設計」**を担う設計・検証ツールである。**車載 ACS の追従制御・runtime 管制（モニタリング/指示配信/CAS/ODS）・認証/OTA/ログ基盤は FRS スコープ外**（[REQUIREMENTS.md §2.2](REQUIREMENTS.md)）。本書はその前提で「FRS が担うべき範囲」に絞って突き合わせる。

凡例: ✅=カバー / ◐=部分 / ❌=ギャップ（要検討）/ ▭=スコープ外（FMS本体/車載）

---

## 1. S-00 運航前データセット準備（B-00-01〜15 / ADT SysRS-F-001〜010）

| ADT 要求 | 内容 | FRS 対応 | 状態 | 備考・ギャップ |
|---|---|---|---|---|
| F-001 / B-00-01 | ティーチング走行軌跡→走路ポリゴン/エリア境界候補の可視化 | LAS点群→costmap→drivable で**地形ベースに走行可能域を生成** | ◐ | **アプローチが異なる**。FRS は走行軌跡ティーチングではなく地形計測ベース。**ギャップ: ティーチング走行軌跡（走行データ）の取込・走路ポリゴン化が無い**。ADT 今G1 は △(Provider) のため代替として地形ベースは妥当だが、走路ティーチング併用は要検討 |
| F-002 / B-00-02 / E-00-B | エリア設定（無人/立入制限/積込/排土/駐機）＋**包含矛盾・境界重複・必須エリア欠落の自動検知** | ポリゴン作図（NoGoZone/containment/切り返しゾーン）あり | ❌ | **エリア種別体系（5種）と完全性検知が無い**。FRS の area は汎用ポリゴンのみ。SRS-SF-B-001（GeoFence 前提）の充足検証ができない。**重要ギャップ** |
| F-003 / B-00-03 / E-00-C | 制限車速をエリア/Static route セグメントに紐付け保存、物理上限超過は拒否 | 速度プロファイル v(s) は**車両性能から生成**。エリア別制限車速の設定・紐付けは無し | ❌ | [REQUIREMENTS.md FRS-O-02](REQUIREMENTS.md) 既出。**ギャップ: エリア/区間別制限車速の設定 UI と機種上限超過バリデーション** |
| F-004 / B-00-04 | Static route 保存→Dynamic route 生成の骨格データ | 経路生成＋ルート保存（savedRoutes）、分岐（junction）あり | ✅ | Static/Dynamic の用語区別は明示していないが、保存経路＋寄り付き＋分岐で機能的に対応 |
| F-005 / B-00-05 / E-00-E | 駐機パドックパターン（位置・向き）の手動設定 | 無し（姿勢指定は寄り付き target で部分代替） | ❌ | **ギャップ: 駐機エリアの複数車両配置パターン定義**。駐機エリア外指定の拒否（E-00-E）も無し |
| F-006 / B-00-06 | Dumping point（排土位置・向き）の設定 | 寄り付き target pose（位置＋方位）で表現可能 | ◐ | 寄り付きの目標姿勢として設定可。ただし「排土エリア内の point 管理」という体系は無し |
| F-007 / B-00-07 | 排土動作マクロ（ベッセル動作） | — | ▭ | 車載動作。FRS スコープ外 |
| F-008 / B-00-08 | 車両ID×機種プロファイル紐付け・登録 | 機種プロファイル選択・諸元オーバーライドあり | ◐ | プロファイルは充実。**車両ID登録・管理コンソール・重複拒否（E-00-G）は無し**（FMS本体側機能） |
| F-009 / B-00-14 | データセット承認・バージョン管理（承認者/日時、ロック） | project 保存＋layer version はあるが**承認フロー/ロックは無し** | ◐ | SRS-SF-G-007 準拠の承認ゲート・鮮度/差分アラートが無い |
| F-010 / B-00-13 | **マップ検証（走行シミュレーション）**: 逸脱・到達不能・デッドロックの事前検知 | 単一経路の安全検証あり。フリート sim が部分該当 | ❌ | [REQUIREMENTS.md FRS-O-03](REQUIREMENTS.md) 既出。**ギャップ: データセット全体の到達可能性/デッドロック事前検証** |
| B-00-09/10 | 車速制限エリア／侵入禁止エリア設定 | **進入禁止（NoGoZone）→回避経路生成は実装** | ◐ | 侵入禁止は ✅ 相当（経路回避）。車速制限エリアは ❌（F-003 と同根） |
| B-00-11 | 3D点群自動 Dynamic Segmentation マップ | costmap/drivable（勾配・粗さ・形態学）で**地形セグメント化を実装** | ◐ | ADT でも Goal-TBD の将来要件。FRS の地形ベース生成はむしろ**先行実装**。ただし「Dynamic Segmentation」（点群クラス分類）とは手法が異なる |
| E-00-D | Static route のエリア外逸脱を強調表示 | drivable 外/NoGo を安全検証で逸脱区間として検出 | ◐ | drivable に統合された形で検出。「エリア境界」概念が無いため厳密一致ではない |

**S-00 総括**: FRS は **F-004（経路）・B-00-09/10 侵入禁止回避・B-00-11 地形セグメント化**で上位を満たす（一部先行）。一方、**エリア種別体系＋完全性検知（F-002）・制限車速（F-003）・パドック（F-005）・データセット承認/検証（F-009/010）**が主要ギャップ。これらは ADT 今G1 で △/- の項目が多く、優先度判断は上位の世代計画に委ねられる。

|---|---|---|---|
| F-021/022 | 制限車速内の経路追従走行・運航ループ継続 | — | ▭（車載追従） |

## 4. 複数台協調（ADT S-10, F-080〜090）

| ADT 要求 | 内容 | FRS 対応 | 状態 |
|---|---|---|---|
| F-080 | Conflict Point（すれ違い/分離/合流/交差）の時空間事前演算 | `detect_conflicts`（交差・共有区間検出、区間提示） | ◐ |
| F-081 | Dispatch 最適化（行先・発進・経路の全体最適、スループット最大化） | 無し | ❌ |
| F-082 | 車間距離管理・追従速度指示 | フリート sim でギャップ確保はあるが車間管理ロジックは簡易 | ◐ |
| F-083 | すれ違い待避所/拡幅区間での通過順調停 | **待避所（passing bay）設定＋自動挿入**を実装 | ◐〜✅ |
| F-084/085/086 | 分離/合流/交差点の Mutex・通過順・デッドロック解消 | フリート sim で**区間予約（Mutex）・優先順位・デッドロック検出**を実装 | ◐ |
| F-088 | 一方通行の逆走禁止（経路設計段階で排除） | 無し | ❌ |

## 8. FRS が上位に対して持つ独自価値（先行/補完）

- **地形ベースの走行可能領域生成**（LAS→costmap→drivable）: ADT B-00-11（自動 Dynamic Segmentation, Goal-TBD）を**先行実装**。
- **多アルゴリズム経路生成＋運動学検証**（spline/dubins/grid・hybrid A*/reeds-shepp/RRT*、Elastic Band、R_min 保証）: ADT F-023/F-024（Dynamic route/SwitchBack, Gen2/Goal）の**設計検証手段**を提供。
- **配信前の機械的安全検証**（フットプリント/R_min/操舵/勾配/離隔、配信可否＋不可理由）: ADT の安全要求群（StRS-S-016 ODD 監視等）を**設計段階で前倒し検証**。
- **寄り付きの候補競合＋コスト関数設計**: ADT F-025（Spotting）の設計探索ツール。
- **フリート競合検出/待避 sim**: ADT S-10（今G1=-）の**先行プロトタイプ**。

> つまり FRS は ADT の **「運航前にデータセットと経路を設計し、車載へ配信する前に運動学・物理・幾何で検証する」**工程を、ADT の世代計画より**前倒し・可視化**して実装している位置づけ。ギャップ G-01/G-02 は、その工程を ADT の FMS スコープ（エリア体系・制限車速）と整合させるための主要な不足項目。

## 9. 推奨アクション

1. **G-01/G-02 を要件化**（FRS-SysRS への追加）: エリア種別 enum とエリア完全性検知、エリア/区間別制限車速。S-00 の中核であり優先度高。
2. **G-06 を即対応**: 寄り付き精度しきい値（±0.5m/±5°）の合否を safety/metrics に追加（低コストで充足）。
3. **G-03/G-05 を中期計画**: データセット検証・承認/バージョン管理。FRS の「配信前検証ツール」価値を強化。
4. **G-08 はスコープ確定待ち**: ADT S-10（FRS-O-01）と役割分担を合意してから着手。
5. **用語整合**: FRS docs に Static/Dynamic route・エリア種別・Spotting/Dumping point の ADT 用語を明示的に対応づけ（一部 [REQUIREMENTS.md §3](REQUIREMENTS.md) で実施済、エリア種別を追補）。
