## 1. 背景・目的

### 1.1 背景

無人化施工（自律ダンプ・自律ブルドーザ等）では、車両を自動走行させる前に **現場地形から「どこを・どの経路で・どの速度で走れるか」を設計し検証する**工程が不可欠である（ADT ConOps §5 S-00）。この工程は従来、計測データの手作業処理・属人的な経路引き・机上の安全確認に依存しており、(a) コストマップ／走行可能領域の生成が標準化されていない、(b) 生成経路が車両の運動学（最小旋回半径・操舵速度）・物理（勾配・転倒）・幾何（車体包絡線）の制約を満たすか機械的に検証されない、(c) 寄り付き（切り返しを伴う精密な停止位置への接近）の設計手段がない、という課題がある。

### 1.2 目的

FRS は、**LAS 点群 → コストマップ → 走行可能領域 → 経路生成（静的/動的）→ 軌道最適化 → 安全検証 → 配信（CSV/GeoJSON）** という FMS 標準パイプラインを、地図上で対話的に実行・検証できる統合ツールを提供する。最終成果物は **速度プロファイル付きの配信可能な trajectory** と、その **配信可否判定（不可理由つき）** である。

主な狙い:
- 運航前データセット準備工程（ADT S-00）の **標準化・可視化・検証可能化**
- 車両運動学・物理・幾何制約を満たす経路の **自動生成と機械的な安全検証**
- 寄り付き（切り返し 0/1）軌道の設計・再生
- 複数台運用に向けた **ルート競合検出・待避・フリート走行シミュレーション**（進行中）
- 自然言語（AI アシスタント）による工程オーケストレーション（**安全判定はルール固定**、AI はあくまで補助）

### 1.3 設計思想（制約ベースを主・AI を補助）

経路の「ブラックボックス生成」ではなく、**制約ベースの生成 → ルール/幾何/物理による安全判定の固定**を中核に置く。AI は工程のオーケストレーション・パラメータ調整・状態確認に限定し、**最終的な配信可否判定に AI を介在させない**（→ FRS-StRS-S-001）。

## 2. スコープ

### 2.1 In-Scope（本ツールが含む）

| 区分 | 内容 |
|---|---|
| **マップ生成** | LAS/LAZ 点群からのコストマップ（生 cost / DSM / 表示用 RGB COG）生成、走行可能領域（drivable）生成・編集 |
| **エリア設定** | ポリゴン（進入禁止 NoGoZone・包含 containment・切り返しゾーン）の作図・管理 |
| **経路生成** | 始点/経由/終点からの経路生成（spline / dubins / grid A* / hybrid A* / reeds-shepp / RRT*）、最小旋回半径保証、Elastic Band 洗練 |
| **寄り付き** | 切り返し 0/1 の接近・退出軌道生成、コスト関数による候補比較、再生 |
| **車両管理** | 機種プロファイル（HD785/HD605/HM400/CD110R）の選択と諸元の可逆オーバーライド |
| **解析・安全検証** | κ / dκ-ds / 操舵 / 勾配 / 速度プロファイルの解析、安全検証（配信可否＋不可理由） |
| **複数台（進行中）** | ルート競合検出、待避所（passing bay）設定、フリート走行シミュレーション |
| **可視化** | 2D 地図（OpenLayers, EPSG:6677 ネイティブ）、3D（点群/DSM メッシュ） |
| **永続化・IO** | プロジェクト保存/読込、CSV/GeoJSON エクスポート、JSON 入出力 |
| **AI アシスタント** | マルチプロバイダ LLM による工程オーケストレーション（tool-use） |
| **座標系** | JGD2011 平面直角座標系（EPSG:6669–6687）対応、起動時/実行時の作業座標系設定 |

### 2.2 Out-of-Scope（本ツールが含まない）

- **車両への実配信・実走行制御**（ACS/車載側の領分。FRS は配信可能な trajectory を出力するところまで）
- **リアルタイム運航管制・フリート監視**（稼働中の車両モニタリング・指示送信は FMS 本体の領分）
- **複数台の本番ディスパッチ最適化**（FRS のフリート機能は競合検出と単純シミュレーションに留まる）
- **ODS/CAS 等の車載安全機能**（検知・回避は車載 ACS／FMS 中央制御の領分）
- **認証/アクセス制御・OTA・監査ログ基盤**（FMS 製品本体の管理機能）
- **マルチユーザー同時編集・サーバー集中運用**（現状はローカル単独運用前提）

### 2.3 上位パッケージとの関係

FRS は ADT の **FMS スコープ（ConOps §2.1-A）のうち「自動運転車両の動作定義（マップ作成 / エリア設定 / ルート設定 / 制限車速）」と S-00 運航前データセット準備**に対応する実装・検証ツールである。FRS が出力する Static route / Dynamic route / 寄り付き軌道・速度プロファイルは、ADT SysRS-F-001〜010・F-021〜029（経路追従・Spotting）の入力データセットに相当する。

## 3. 用語

`unmanned-requirements/Glossary.md` を継承する。FRS 固有・重要語のみ以下に補足する。

| 用語 | 意味 |
|---|---|
| **コストマップ（costmap）** | 点群から生成する走行コスト格子。勾配・粗さを重み付けし、閾値超過は障害物値（obstacle_value）に倒す |
| **走行可能領域（drivable）** | コストマップを閾値/形態学処理で2値化した走行可能マスク。include/exclude ポリゴンで可逆編集 |
| **寄り付き（spotting）** | 積込/排土等の目標姿勢（位置＋方位）へ精密に接近する操作。切り返し（switchback）を伴う場合がある |
| **フットプリント（footprint）** | 車体包絡線ポリゴン。経路上で走行可能領域に収まるかの衝突判定に使用 |
| **作業座標系（working CRS）** | UI・計算で用いる JGD2011 平面直角座標系（既定 EPSG:6677）。精度保持のため Web メルカトル等へ再投影しない |
| **配信可否（安全検証）** | 車体包絡線・R_min・操舵・勾配・離隔の統合チェック結果（passed + 不可理由） |
| **COG** | Cloud Optimized GeoTIFF。ラスタ表示・配信形式 |
| **Static / Dynamic route** | ADT 用語を継承（固定経路 / 動的生成経路）。FRS では経由点経路 / 寄り付き軌道が対応 |

## 6. システム要求（SysRS / F·P·I·S·R）

> §5 StRS を、FRS が満たすべき技術要求（検証可能・一意）へ展開する。各要求の実装は [DESIGN.md](DESIGN.md) で具体化される。**実装状況**列は現コードに対する状態。

### 6.1 Functional（機能要求）

#### マップ・コストマップ（S-00 マップ作成）

| SysRS-ID | 要求文 | 実装 | 由来 | 関連 StRS |
|---|---|---|---|---|

| FRS-SysRS-F-002 | システムは、生成コストマップから **DSM の間引き格子**（3D 可視化用）を返せなければならない。 | ● | 可視化 | FRS-StRS-Q-009 |
| FRS-SysRS-F-003 | システムは、勾配しきい超過セルを**障害物値（obstacle_value）に倒し**、走行不能セルを後段（領域生成・経路衝突判定）が一意に識別できる形で保持しなければならない。 | ● | ADT SysRS-F-010 | FRS-StRS-S-003 |

#### 走行可能領域（S-00 エリア生成）
